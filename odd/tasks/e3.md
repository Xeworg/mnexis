# Mnexis E3 — Tokenizer exacto y fixture congelado

> E3 implementation ODD. Closes PRD §9 "memory_context" exact mode (A-07)
> and lays the groundwork for the A-08/A-09 quality gates. The supported
> tokenizer v1 is the std-only, BPE-lite counter documented here; the
> frozen 500-memory/150-query fixture is reproduced from
> `docs/t14-fts5-benchmark.md` and is a development tool, not a
> production command.

## Specs

S24 — `mnexis context` round-trip: the CLI accepts `--namespace`,
`--token-budget`, `--tokenizer-id`, `--max-items`, `--budget-mode
exact|estimated`, and a `TASK` argument. Default mode is `estimated`
for backward compatibility (the E2 partial).

S25 — A-07 invariant: when `budget-mode exact` is requested with the
supported tokenizer (`supported-tokenizer-v1`), the response's
`tokens_used` equals `token_count_v1(serialised_envelope)` and never
exceeds `token_budget`. An unsupported `tokenizer_id` in exact mode
raises `BudgetTooSmall` (exit 7).

S26 — `token_count_v1` is deterministic, std-only, and an upper bound:
`count(s) <= s.len()` for every UTF-8 string. Each non-ASCII character
is one token; each ASCII alphanumeric run is one token; each ASCII
non-alphanumeric character is one token; whitespace runs collapse.

S27 — Pipeline output envelope carries `items`, `retrieval_mode`,
`budget_enforcement`, `tokens_used`, `bytes_used`, `tokenizer_id`,
`index_status`, `warnings`, optional `empty_reason`. Each item carries
`uuid`, `revision`, `namespace`, `content`, `memory_type`, `state`,
`topic_key`, `assertion_basis`, `created_at`.

S28 — Diversity: no duplicate `topic_key`, no exact duplicate content.
Eligibility: drop deleted, drop out-of-window, drop memory_types not
requested, drop non-active when `active_only`.

S29 — Deviations: E3 does NOT add the 500-memory/150-query fixture
runner to the binary (PRD §15 quality gate stays in development tools
per e2-core §10; E3 ships the supported tokenizer and the exact mode
the gate would measure against). The fixture exists at
`fixtures/e0/` and `examples/t14_eval.rs` already consumes it.
